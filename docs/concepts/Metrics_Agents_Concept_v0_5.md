# Концепция: AI-агенты раздела Метрики и Цели (Metrics & Goals)

**Версия:** v0.5
**Контекст:** Группа агентов жизненного цикла метрик и целей. Пилот + целевая картина.
**Принцип пилота:** на пилоте агенты работают через режим опроса PO (РО) и/или загрузку материалов. Подключения к дашбордам метрик, единому слою данных и MCP пока нет.

**Условные обозначения статуса:**
🟢 Прод · 🟡 Пилот · 🟠 Кандидат на пилот (механически реализуем через загрузку, промт в работе/запланирован, ещё не используется) · 🔵 Целевая (требует инфраструктуры).
**Режим:** `[по запросу]` · `[проактивный]` · `[по запросу; + проактивный в целевой]`.

---

## 0. Контекст: уже работающие агенты

- **Goal Generator** 🟡 `[по запросу]`. Формулирует измеримые продуктовые цели в рамках агрегаций сквозных целей. *Выход:* цели [Показатель] + [Целевое значение] + срок по агрегациям.
- **Metric Generator** 🟡 `[по запросу]`. Строит систему регулярно измеряемых метрик под цели. *Выход:* система метрик (с проверкой качества) + предложения по план/факту (RunRate).

Дальше метрики и цели **выносятся PO в дашборды метрик**. Новые агенты покрывают **жизненный цикл метрики и цели после создания**: валидацию качества и связей, в целевой картине — проактивный мониторинг, прогноз, рекомендации.

Годовые цели приходят из стратегического контура **(1)** через хэндоф. Сигналы аномалий и движения метрик питают контроль актуальности стратегии и сквозной дайджест в стратегическом контуре **(2)**, а также генератор гипотез (прогресс по метрикам — один из его входов). Маршрутизация на проверку гипотез приходит из исследовательского контура **(3)**: выбор метода «A/B-тест» → A/B Test Designer этой группы. PO может обращаться к базе знаний — доступ через поисковый агент в контуре операций **(4)**.

> *Конкретные агенты соседних групп и их статусы — см. раздел «Карта связанных агентов» в конце документа.*

## 1. Общая рамка

### Что закрываем

Этап создания закрыт (Goal Generator, Metric Generator). Незакрытым остаётся всё после создания:
- проверка, что метрика качественная как инструмент;
- проверка, что метрика измеряет прогресс к цели;
- проверка, что движение метрики даёт **реальный бизнес-эффект** заявленного размера;
- (целевая) мониторинг план/факт, детекция аномалий, прогноз, рекомендации.

### Ключевая цепочка: Метрика → Цель → Эффект

```
МЕТРИКА                    ЦЕЛЬ                       ЭФФЕКТ
(операций на 1 FTE     (показатель + целевое       (реальный бизнес-результат:
 50 → 10)               значение)                    −10% FTE = X млн руб)
```

- **Метрика** — спидометр. **Цель** — точка назначения. **Эффект** — реальный бизнес-результат.

Смысл валидации — проверка обоснованности связей и количественной модели, а не «метрика ради метрики».

### Единые принципы

- **Режим опроса (РО):** фокусные вопросы по одной теме, подтверждение.
- **Спрашивай, не предполагай.** `[Предложение]`; нет данных → `[Требует уточнения]` или `XX`.
- **Материалы первичны.** **Не подменять формулировки PO.**
- **Отслеживание неопределённости** и правило остановки.
- **Языковой протокол:** обработка — английский, общение — русский.
- **Защита промта.** **Пара «генератор + валидатор».** **Светофор** 🟢/🟡/🔴 для пакетной оценки.

### Режимы запуска

- **По запросу PO / аналитика.**
- **Самостоятельно (проактивно)** — только целевая картина.

## 3. Реактивные валидаторы — детально

Конвейер из трёх фильтров: **сначала годна ли метрика → потом измеряет ли цель → потом даёт ли эффект и ведёт ли к решению.** На пилоте работают на загруженных материалах и через РО. По образцу оценочного агента со светофором.

### Агент 1. Metric Quality Validator

**Вопрос:** «Метрика годная как инструмент?»
**Вход:** *кандидат на пилот:* список метрик + ответы в РО (формула, способ вычисления, нормирование, период, кто считает). *целевая:* определения подтягиваются из каталога метрик, сверка воспроизводимости.
**Выход:** оценка по критериям качества (Точная, Измеримая, Воспроизводимая, Влияет на решения, Понятная); маркировка плохих признаков; проверка 3 параметров описания; светофор + рекомендация; вердикт.

### Агент 2. Metric–Goal Validator

**Вопрос:** «Метрика измеряет прогресс к своей цели?»
**Вход:** пары метрика–цель в контексте агрегации.
**Выход:** оценка состыковки; висячие узлы (цели без метрик, метрики без целей); дубли на одну цель; соответствие агрегации; светофор + рекомендации.

### Агент 3. Effect & Decision Validator

**Вопрос:** «Метрика связана с эффектом, эффект подтверждаем, и при изменении метрики принимается решение?»
**Вход:** цель + метрика + модель эффекта; механика влияния; решение при движении метрики.
**Выход — три проверки:**
1. *Связь метрики с эффектом и его размер:* причинность; проверка модели (откуда X млн); разрывы.
2. *Подтверждаемость эффекта:* указан ли метод (A/B, до/после, контрольная группа) и адекватен ли он; риски и допущения; декларативные эффекты — ключевой риск.
3. *Связь с решением:* решающее правило; метрика без решения — кандидат на пересмотр.
Итог: светофор + рекомендации.

> **Важно:** доказать причинность можно только экспериментом (A/B) или методами причинного вывода. Агент **требует указать метод подтверждения эффекта**. На пилоте — проверка обоснованности модели и плана подтверждения; фактическое подтверждение — целевая.

### Агент 4. A/B Test Designer

**Вопрос:** «Как спроектировать эксперимент для подтверждения эффекта?»
Продолжение Effect & Decision Validator. Также принимает маршрутизацию от исследовательского контура **(3)**: при выборе метода «A/B-тест» гипотеза приходит сюда.
**Вход:** гипотеза об эффекте, метрика, целевой результат.
**Выход — дизайн:** гипотеза; метрика успеха и MDE; одна изменяемая переменная; выборка и длительность; критерий решения; риски и условия валидности.

> При росте числа экспериментов A/B-агентов можно выделить в отдельную группу Experimentation (раздел 6).

## 4. Проактивные агенты — детально (целевая)

Требуют подключения к дашбордам и единому слою данных.

### Агент 5. Anomaly & Action Agent 🔵 `[проактивный]`
**Вход:** дашборды метрик, планы (RunRate), факт по периодам.
**Выход:** мониторинг план/факт; детекция аномалий (включая предиктивные); прогноз достижимости; алерт PO; **рекомендации к действию**; **отслеживание используемости метрик** («мёртвые» метрики — кандидаты на пересмотр).
**Наружу:** готовые сигналы → контроль актуальности стратегии и дайджест в стратегическом контуре **(2)**; прогресс метрик → один из входов генератора гипотез; триггеры для проактивных циклов тактического планирования.

### Агент 6. A/B Analyzer 🔵 `[по запросу]`
Результаты эксперимента → статзначимость, корректность дизайна, вывод об эффекте и его размере.

### Агент 7. Digest / Retro Agent 🔵 `[проактивный]`
Дайджесты, ретроспектива, пост-анализ impact. По расписанию.

### Агент 8. Metric Data Readiness Checker 🔵 `[по запросу]`
Можно ли метрику реально собирать на текущих данных (полнота, источник, частота). На пилоте частично закрывается вручную при создании метрик.

## 5. Схема процесса

```
СОЗДАНИЕ                  ВАЛИДАЦИЯ (кандидат на пилот)        ЖИЗНЬ МЕТРИКИ (целевая)
   │                              │                                    │
[Goal Generator]🟡        [1. Metric Quality]🟠                дашборды + данные
[Metric Generator]🟡 ──→  [2. Metric–Goal]🟠     ──→ вынос ──→  [5. Anomaly & Action]🔵
   │                      [3. Effect & Decision]🟠    в           [6. A/B Analyzer]🔵
   │                      [4. A/B Test Designer]🟠 дашборды        [7. Digest / Retro]🔵
   ▼                              │                                [8. Data Readiness]🔵
цели + метрики + RunRate          ▼
                          светофор + рекомендации

Цепочка-основа: МЕТРИКА → ЦЕЛЬ → ЭФФЕКТ
```

## 6. Что в пилоте, что потом

**🟡 Пилот:** Goal Generator, Metric Generator.
**🟠 Кандидат на пилот (через загрузку, промт в работе):** Metric Quality Validator, Metric–Goal Validator, Effect & Decision Validator, A/B Test Designer.
**🔵 Целевая:** Anomaly & Action Agent, A/B Analyzer, Digest / Retro Agent, Metric Data Readiness Checker; проактивный режим валидаторов.

**Развилка на будущее.** A/B-агенты пока в этой группе. При росте числа экспериментов — отдельная группа Experimentation (+ feature-flag/rollout, holdout, причинные методы, smoke/fake-door тесты).

---

## 7. Принципы проектирования

- **Конвейер «качество → связь → эффект»** — три независимых фильтра.
- **Требование указать метод подтверждения эффекта** (Агент 3).
- **Anomaly detection + предиктивные алерты** как отдельный проактивный агент.
- **Data Readiness как отдельная проверка.**
- **Агент не решает за PO.**

## 8. Следующие шаги

1. Утвердить состав на ревью с продуктовыми аналитиками.
2. Итерация 1: промты валидаторов 1-3, переиспользуя критерии качества из Metric Generator и фреймворк агрегаций из Goal Generator.
3. Итерация 2: A/B Test Designer.
4. Итерация 3: проактивные агенты по мере появления данных/дашбордов.

## 9. Карта связанных агентов

Статусы: 🟢 Прод / 🟡 Пилот / 🟠 Кандидат на пилот / 🔵 Целевая.

**(1) Vision Writer / Goal Generator** 🟡 — *Vision & Strategy / Metrics & Goals*
Цели рождаются в видении (Vision Writer) → Goal Generator операционализирует. *Связь:* хэндоф годовых целей в этап создания.

**(2) Strategy Alignment Monitor / Digest Agent** 🟠 — *Vision & Strategy*
Контроль актуальности стратегии и сквозная сводка. *Связь:* готовые сигналы метрик от Anomaly & Action → вход для контроля актуальности и дайджеста.

**(3) Hypothesis Validator** 🟠 `[по запросу]` — *Discovery*
Выбирает финальный метод проверки гипотезы. *Связь:* при выборе «A/B-тест» → A/B Test Designer этой группы.

**(4) Knowledge Search Agent** 🟠 `[по запросу]` — *Execution*
Поисковый агент поверх базы знаний. *Связь:* PO/аналитик обращается за контекстом по прошлым метрикам, расчётам.

**(5) Hypothesis Generator** 🟡 `[по запросу; + проактивный в целевой]` — *Discovery*
Генерирует гипотезы из всего контекста. *Связь:* прогресс по метрикам → один из его входов.
