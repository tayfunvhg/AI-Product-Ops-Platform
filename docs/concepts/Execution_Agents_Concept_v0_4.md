# Концепция: AI-агенты раздела Операции (Execution)

**Версия:** v0.4
**Контекст:** Группа агентов операционного исполнения. Пилот + целевая картина.
**Принцип пилота:** на пилоте агенты работают через режим опроса PO (РО) и/или загрузку материалов (запросы, PRD, бэклог, саммари встреч, выгрузки дашборда, ссылки на вики/Confluence и доски в трекере). Подключений к трекерам, Confluence и дашбордам через MCP пока нет.

**Условные обозначения статуса:**
🟢 Прод · 🟡 Пилот · 🟠 Кандидат на пилот (механически реализуем через загрузку, промт в работе/запланирован, ещё не используется) · 🔵 Целевая (требует инфраструктуры).
**Режим:** `[по запросу]` · `[проактивный]` · `[по запросу; + проактивный в целевой]`.

---

## 0. Контекст: уже работающие агенты

- **Brief Writer** 🟡 `[по запросу]`. Заказчик приносит сырую идею → агент опрашивает (проблема, ценность, эффекты, связь со стратегией) → структурированный бриф-гипотеза. Качество проверяется на этапе PRD, отдельная валидация брифа не нужна. *Выход:* карточка-гипотеза для бэклога.
- **Scriber** 🟢 `[по запросу]`. Записывает встречу и присылает итоги (саммари). Сам не разделяет, что в задачи, а что в фиксации — это делает Meeting Output Processor.

Новые агенты группы покрывают **создание и проверку операционных артефактов** (PRD, задачи, презентации, статус-отчёты), **обработку выхода встреч**, **поиск по базе знаний** и **анализ производственных процессов**.

---

## 1. Общая рамка

### Что закрываем

Операционное исполнение — «регулярка»: рутинные артефакты и действия. Группа закрывает:
- формализацию запроса в бриф (существует) и далее в **PRD** (генерация + валидация);
- **декомпозицию** скоупа на задачи и их **оценку**;
- **поиск дублей** требований и задач;
- **обработку итогов встреч** (задачи / action items / темы);
- **генерацию презентаций** из любого продуктового контекста;
- **подготовку регулярных статус-отчётов** для комитетов;
- **поиск по базе знаний** — для PO и для других агентов;
- **анализ производственных (Delivery) процессов** и рекомендации.

Приоритизированный бэклог и квартальные карточки приходят из контура тактического планирования **(1)**; контекст PRD — видение и цели из стратегического контура **(2)** и проверенные гипотезы/персоны из исследовательского контура **(3)**; метрики продукта — из контура формирования метрик **(4)**. Свежие брифы питают генерацию гипотез в исследовательском контуре **(3)**.

> *Конкретные агенты соседних групп и их статусы — см. раздел «Карта связанных агентов» в конце документа.*

### Единые принципы

- **Режим опроса (РО):** 2-4 вопроса за раз, подтверждение.
- **Спрашивай, не предполагай.** `[Предложение]`; нет данных → `[Требует уточнения]` / `XX`.
- **Материалы первичны. Не подменять формулировки PO.**
- **Отслеживание неопределённости** и правило остановки.
- **Языковой протокол:** обработка — английский, общение — русский.
- **Агент не решает за PO** (и в проактивном режиме).
- **Пара «генератор + эватор»** на ключевой артефакт (PRD). Бриф валидируется на PRD; презентация и статус-отчёт — без эватора. **Защита промта.**

### Режимы запуска

- **По запросу PO / аналитика / СТО.**
- **Самостоятельно (проактивно)** — целевая картина, требует дашбордов/трекера/Confluence.

## 3. Агенты детально

### Агент 1. PRD Writer 🟡

**Вход:** *пилот:* бриф (от Brief Writer), проверенные гипотезы из исследовательского контура **(3)**, контекст из стратегического контура **(2)** (видение, цели), метрики из контура формирования метрик **(4)**, **ссылка на вики/Confluence** и **доску в трекере**, РО. Без MCP — PO передаёт ссылки + копирует содержимое, либо контекст из базы знаний (раздел 5.1). *целевая:* агент сам забирает по ссылкам через MCP.
**Выход:** *пилот:* PRD «на руки» (проблема, цель, пользователи, требования, метрики успеха, scope/out-of-scope, риски); PO копирует в Confluence и заводит задачи. *целевая:* агент сам создаёт страницу и задачи с заполненными полями.
**Чего не делает:** не приоритизирует (тактика), не декомпозирует (Агент 3).

### Агент 2. PRD Evaluator 🟠

Эталонная пара к PRD Writer, по образцу оценочных агентов стратегического контура **(5)**.
**Критерии (черновик, ревью с аналитиками):** ясность проблемы; измеримость метрик успеха; чёткость scope/out-of-scope; связь с целями; проработка рисков; отсутствие противоречий.
**Выход:** *пилот:* отчёт «на руки». *целевая:* автокомментарий к странице PRD в Confluence.

### Агент 3. Task Decomposer 🟠
**Вход:** PRD/скоуп, ссылки на вики и трекер, РО.
**Выход:** *пилот:* дерево задач «на руки». *целевая:* автозаведение в трекер.

### Агент 4. Task Estimator 🟠
**Вход:** задачи (из декомпозиции или готовые).
**Выход:** *пилот:* оценка «на руки» с допущениями и `[Предложение]`; подсветка высокой неопределённости. *целевая:* оценки в полях задач.
**Калибровка:** в целевой опирается на фактические Delivery-метрики (реальные Lead Time / Cycle Time по типам задач) от Delivery Analytics Agent (Агент 10) — оценки калибруются по истории.
**Особенность:** работает и без декомпозиции.

### Агент 5. Duplicate Finder 🟠
**Вход:** *пилот:* одна загрузка (бэклог или набор PRD) + ссылки. *целевая:* сквозной поиск по трекеру и Confluence через MCP.
**Выход:** список потенциальных дублей с обоснованием схожести + рекомендация.
**Связь с входной воронкой:** свежий бриф перед попаданием в бэклог имеет смысл прогонять через Duplicate Finder.

### Агент 6. Meeting Output Processor 🟠
**Вход:** саммари Scriber'а. *пилот:* копированием. *целевая:* автоприём.
**Выход — три потока:** кандидаты в задачи (с черновой формулировкой); action items (фиксации); темы для проработки.
*пилот:* «на руки». *целевая:* кандидаты в задачи → трекер (по подтверждению PO), фиксации/темы → Confluence.

### Агент 7. Presentation Generator 🟠
Сквозной агент. *Артефакт → слайды* («вынеси видение/OKR/PRD на слайды»); *контекст-запрос → презентация* (собирает контекст из выходов других агентов, опирается на базу знаний — раздел 5.1).
**Эватор не делаем.**

### Агент 8. Status Report Agent 🟠 `[по запросу; + проактивный в целевой]`
**Вход:** статус задач, прогресс по целям, риски, решения; ссылки.
**Выход:** статус-отчёт (сделано / в работе / риски / решения / next steps). *пилот:* «на руки». *целевая:* автосоздание страницы в Confluence + проактивно к датам комитетов.
**Эватор не делаем.**

### Агент 9. Knowledge Search Agent 🟠
Поисковый агент поверх базы знаний (раздел 5.1).
**Вход:** запрос PO в свободной форме.
**Выход:** релевантные фрагменты + источники + саммари. Нет результата — явно сообщает (без галлюцинаций).
**Покрытие:** *пилот:* только загруженные PO материалы. *целевая:* Confluence/вики/трекер через MCP.
**Сквозной характер:** агентом пользуется PO любой группы.

### Агент 10. Delivery Analytics Agent 🟠 `[по запросу; + проактивный в целевой]`
Смотрит на **производственные (Delivery) метрики** — T2M, Lead Time, Cycle Time, Flow Efficiency, Delivery time, throughput, зависающие задачи — и даёт **процессные рекомендации** (декомпозиция, планирование, ресурсы, зависающие задачи, есть ли система).
**Режимы:** *по запросу (пилот):* PO/СТО просит консультацию через загрузку выгрузок/скринов дашборда + ссылку на трекер. *проактивно (целевая):* сам смотрит дашборд, детектирует проблемы, приносит рекомендации (нужен MCP/API).
**Границы:** работает с **процессными метриками исполнения**; это не мониторинг продуктовых метрик (контур мониторинга **(6)**) и не оценка зрелости (ИЗИ/ОКИИ, вне группы). vs **анализ рисков квартального плана (контур тактики **(7)**):** риски — про конкретный план (что сорвёт OKR); Delivery Analytics — про системное здоровье производства.
**Поставляет наружу:** фактические Delivery-метрики → калибровка Task Estimator (Агент 4); сводку процессов → источник сквозного дайджеста в стратегическом контуре **(8)**.

## 4. Сквозные возможности и стандарты группы

### 4.1. База знаний (RAG) — сквозная возможность

> **Важно:** база знаний (RAG) — *сквозная возможность*, обслуживающая все группы. Временно описана здесь (отдельной группы Data ещё нет, основные потребители — в Execution). При формировании Data — переезжает туда.

**Что это:** индексация внутренних материалов и поиск релевантного контекста.
**Два режима:** *инфраструктурный* (агенты внутри обращаются за контекстом — PRD Writer, Presentation Generator, Delivery Analytics); *самостоятельный* (через Knowledge Search Agent PO ищет напрямую).
**Пилот:** индексирует только материалы, загруженные PO вручную (индекс не растёт сам).
**Целевая:** через MCP индексирует Confluence/вики/трекер автоматически; переезжает в группу Data.

### 4.2. Стандарт I/O для артефакт-производящих агентов

| Применяется к | Pilot вход | Целевой вход | Pilot выход | Целевой выход |
|---|---|---|---|---|
| PRD Writer | ссылки + копирование/база знаний | MCP | PRD «на руки» | автосоздание страницы + задач |
| PRD Evaluator | PRD загрузкой | MCP | отчёт «на руки» | автокомментарий |
| Task Decomposer | ссылки на вики + трекер | MCP | задачи «на руки» | автозаведение задач |
| Task Estimator | задачи копированием | MCP | оценки «на руки» | оценки в полях задач |
| Duplicate Finder | одна загрузка + ссылки | сквозной поиск MCP | список «на руки» | автокомментарии |
| Meeting Output Processor | саммари копированием | автоприём от Scriber'а | три потока «на руки» | автозаведение + публикация |
| Status Report Agent | ссылки + копирование | MCP | отчёт «на руки» | автостраница + проактивно |
| Delivery Analytics Agent | выгрузки/скрины + ссылка | MCP | рекомендации «на руки» | проактивные алерты |

**Принцип:** на пилоте — «на руки» (PO копирует), в целевой — автодействие через MCP. Brief Writer следует тому же паттерну на выходе.

### 4.3. Прочие сквозные стандарты

- **Создаём и проверяем, но не решаем за PO.**
- **Пара генератор↔эватор — только для самостоятельного артефакта** (PRD).
- **Процессное ≠ продуктовое.** Delivery-метрики — Delivery Analytics; продуктовые — контур мониторинга; зрелость — ИЗИ/ОКИИ.

## 5. Связи с соседними группами агентов (по функции)

- **Тактика → исполнение:** приоритизированный бэклог и карточки → PRD Writer и Task Decomposer.
- **Исследовательский контур → исполнение:** проверенные гипотезы, персоны → контекст PRD.
- **Стратегический контур → исполнение:** видение, стратегия, цели → контекст PRD и презентаций.
- **Контур формирования метрик → исполнение:** метрики → метрики успеха в PRD.
- **Scriber → Meeting Output Processor:** саммари → классификация (внутри группы).
- **Исполнение → тактика:** свежий бриф → новый элемент бэклога (с проверкой на дубли).
- **Исполнение → исследовательский контур:** брифы → контекст генерации гипотез.
- **Исполнение → стратегический контур:** сводка Delivery-процессов → источник дайджеста.
- **База знаний ← все группы:** обслуживает всех; временно живёт здесь до формирования Data.

## 6. Что в пилоте, что потом

**🟢 Прод:** Scriber.
**🟡 Пилот:** Brief Writer, PRD Writer.
**🟠 Кандидат на пилот (через загрузку, промт в работе):** PRD Evaluator, Task Decomposer, Task Estimator, Duplicate Finder, Meeting Output Processor, Presentation Generator, Status Report Agent (по запросу), Knowledge Search Agent, Delivery Analytics Agent (по запросу).
**🔵 Целевая:** проактивные режимы Status Report Agent и Delivery Analytics Agent; автодействия через MCP (автозапись задач/страниц, сквозной поиск, автосбор отчётов).

## 7. Ограничения на пилоте

- Нет MCP → агенты на загрузках и ссылках с ручным копированием; автозапись, сквозной поиск, проактивные режимы — целевая.
- Нет единых стандартов артефактов → агенты адаптируются.
- База знаний покрывает только материалы, загруженные PO вручную.
- Связь Scriber → Meeting Output Processor на пилоте ручная.

## 8. Что делаем дальше (итерации)

- **Итерация 1:** PRD Evaluator (критерии качества PRD с аналитиками; PRD Writer уже в пилоте).
- **Итерация 2:** Task Decomposer + Task Estimator.
- **Итерация 3:** Meeting Output Processor + Duplicate Finder.
- **Итерация 4:** Presentation Generator + Status Report Agent.
- **Итерация 5:** Knowledge Search Agent + базовый пилотный RAG.
- **Итерация 6:** Delivery Analytics Agent (по запросу), далее проактивный режим по мере MCP.

## 9. Открытые вопросы на ревью

1. Критерии качества PRD (Агент 2) — черновик.
2. Формат статус-отчёта для комитетов — эталонный шаблон.
3. Перечень Delivery-метрик и целевые зоны — из производственного дашборда.
4. Связь Meeting Output Processor с Task Decomposer — автоматически или по подтверждению.
5. Технология RAG на пилоте — выбор векторной базы и формата индексации.

## 10. Карта связанных агентов

Статусы: 🟢 Прод / 🟡 Пилот / 🟠 Кандидат на пилот / 🔵 Целевая.

**(1) Backlog Prioritizer** 🟠 `[по запросу; + проактивный в целевой]` — *Tactical Planning*
Приоритизирует бэклог. *Связь:* приоритизированный бэклог → PRD Writer и Task Decomposer.

**(2) Vision Writer / Strategy Actualizer** 🟡 / 🟠 — *Vision & Strategy*
Формируют видение и стратегию. *Связь:* видение, стратегия, цели → контекст PRD и презентаций.

**(3) Hypothesis Generator + исследовательские генераторы** 🟡 / 🟠 — *Discovery*
Генерируют гипотезы, формируют инсайты и персоны. *Связь:* проверенные гипотезы/персоны → контекст PRD; брифы → контекст генерации гипотез.

**(4) Metric Generator** 🟡 `[по запросу]` — *Metrics & Goals*
Строит систему метрик под цели. *Связь:* метрики → раздел «метрики успеха» PRD.

**(5) Vision Evaluator / Strategy Evaluator** 🟢 / 🟠 — *Vision & Strategy*
Оценивают артефакты по критериям. *Связь:* образец для PRD Evaluator.

**(6) Anomaly & Action Agent** 🔵 `[проактивный]` — *Metrics & Goals*
Мониторит продуктовые метрики. *Связь:* разграничение зон — продуктовые (мониторинг) vs процессные (Delivery Analytics).

**(7) Risk & Mitigation Analyzer** 🔵 `[проактивный]` — *Tactical Planning*
Анализирует риски квартального плана. *Связь:* разграничение зон с Delivery Analytics (план vs процесс).

**(8) Digest Agent** 🟠 `[по запросу; + проактивный в целевой]` — *Vision & Strategy*
Сквозная сводка для PO. *Связь:* сводка Delivery-процессов → один из источников дайджеста.
