# Технический долг

Сознательно отложенные доработки. Зафиксированы по итогам архитектурного аудита
(см. чат «Архитектурный аудит перед агентами»). Прототип намеренно не усложняем —
эти пункты берём, когда появится реальная потребность.

## Отложено

1. **Жёсткий гейт конвейера по распарсенному вердикту эватора.**
   Сейчас гейт мягкий: кнопка «Валидация пройдена» разблокируется после первого
   ответа эватора, а не после реально положительного вердикта. Для прототипа
   достаточно. В целевой версии — парсить вердикт Evaluator (балл/«Ok») и
   открывать следующий этап только при прохождении.
   _Где:_ `src/components/PipelineBoard.tsx` (`canValidate`/`evalReplied`),
   `src/app/api/pipeline/route.ts`.

2. **Парсер Goal Generator (таблица 6 агрегаций А1-А6) + `publishesTo` для
   этапов strategy / goals / classify.** Отложено вместе: публиковать без
   парсера смысла нет, а сами агенты пока в статусе пилот/кандидат.
   - Реальный выход Goal Generator — таблица `| Сквозная цель | Цели продукта |`;
     текущий `parseGoals` переиспользует `parseVision` (паттерн «Целевой/Текущий
     год») и эту таблицу не распознаёт.
   - `strategy-actualizer`, `goal-generator`, `initiative-classifier` не имеют
     `publishesTo`, поэтому в конвейере их артефакты не публикуются.
   _Где:_ `src/lib/parsers.ts` (`parseGoals`), `src/lib/agents.ts`.

3. **Единый id-связанный источник целей ↔ метрик.**
   Цели/метрики сейчас определены в нескольких местах (`VISION.metricsTargets`,
   `RUNRATE_SEED.goals`, `ROADMAP`, `METRICS`) и связаны по строковому имени.
   Нужен один источник с id-связью «цель → метрики». (Формулировки O1/O2 уже
   сведены к единым строкам как точечная мера.)
   _Где:_ `src/lib/mock.ts`, `src/lib/repo.ts`.

4. **Runner/scheduler проактивного режима.**
   Введено только поле `mode` в `AgentDef` (`on-demand`/`proactive`/`both`).
   Самого планировщика/триггеров (Anomaly & Action, Trend Watcher, Digest) нет —
   всё запускается по кнопке. Заложить runner, когда появятся данные/расписания.
   _Где:_ `src/lib/agents.ts` (поле `mode`), новый слой runner — отсутствует.

5. **Прочие точечные улучшения связности:**
   - Вынести демо-данные (`mock.ts`) за слой «источника», по аналогии с
     артефактами.
   - Скоупить демо-данные (метрики, персоны, исследования) по активному
     продукту — сейчас они глобальны, а артефакты и конвейер уже per-product.
   - Удалить висящий эндпоинт `src/app/api/artifacts/route.ts` (не вызывается
     с клиента) либо задействовать его.
   - Свести дубль определения статусов `STATUS_BADGE` (`agents.ts`) и
     `STATUS_CHIP` (`PipelineBoard.tsx`) к одному источнику.
